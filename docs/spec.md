## 設計原則

- **1行 = 1文**。改行が文の終わり。
- 文要素は **定義 / 包含 / 接続** の 3 種類のみ。
- **キーワードを持たない**。図種は構造から自動推論される。
- 符号(reference numerals)を直接 ID として扱う。
- 日英ラベルを 1 ソースで管理する。

---

## 字句

### 符号(ID)

符号は次のパターン:

```
ID := [A-Za-z0-9_*]+
```

| 例 | 用途 |
|---|---|
| `10` `20` `100` | 装置クレームでよくある数値符号 |
| `S100` `S110` | 方法クレームのステップ符号 |
| `K1` `P2_3` `11a` | 英字+数字、`_` も可 |
| `*` | 状態遷移の初期/終端マーカ(黒丸で描画) |

予約記号(ID に使えない): `=` `:` `-` `>` `<` `.` `/` `#` `"` `(` `)` `空白`

### 数値

接続演算子のうち `<-` の `-`、`->` の `-` などは演算子の一部であり、ID と区別するために常に **半角スペースで囲まれる** ことを要求する。

### 文字列リテラル

ダブルクォートで囲まれた任意の文字列。

```
STRING := '"' (任意の文字、ただし " と改行を除く) '"'
```

文字列内の `"` をエスケープする手段は現バージョン非対応(`\"` などは未サポート)。

### 空白と改行

行内の連続する空白(スペース・タブ)は区切り文字。先頭/末尾の空白は無視。
空行(空白のみの行を含む)は無視。

## 文要素

行(コメント除去後)を以下の順に判定する:

1. 行が **定義パターン** にマッチ → 定義として処理
2. 行が **接続パターン** にマッチ → 接続として処理
3. 行が **包含パターン** にマッチ → 包含として処理
4. いずれにもマッチしない → 構文不明エラー

### ① 定義

```
DEF := ID '=' LABEL
```

**意味**: 符号にラベルを付ける。

**例**:
```pdg
10 = 制御装置 / control device
11 = CPU
13 = "I/O インターフェース" / "I/O interface"
```

- `=` の前後の空白は任意(なくても良い)。
- `=` の直後が `>` の場合は接続(`=>`)として扱う(否定先読み)。
- ラベルは [ラベルと多言語](#ラベルと多言語) を参照。
- 同じ ID を 2 回定義すると **警告**(後の定義で上書き)。

### ② 包含

```
CONT := ID ':' ID (' '+ ID)*
```

**意味**: 親が子を内包する関係を表す。

**例**:
```pdg
10 : 11 12 13
```

- 子の符号は **半角スペース区切り**。
- 子が 1 つだけでも可: `10 : 11`
- ネストは別の包含文として書く:
  ```pdg
  100 : 10 20
  10  : 11 12
  20  : 21 22
  ```
- 同じ子を複数の親の下に書くと **未定義動作**(将来定める)。実装は最後の親に従う。
- 包含が存在する図は [ブロック図](#図種の自動推論) として描画される。

### ③ 接続

```
CONN := ID ' ' OP ' ' ID (' '* ':' LABEL)?
OP   := '<->' | '=>' | '->' | '<-' | '.>' | '..' | '-'
```

**意味**: ノード間の線・矢印を描く。

**例**:
```pdg
11 -   12
13 ->  20
30 <-  40
50 <-> 60
70 ..  80
70 .>  80
40 =>  50

13 -> 20 : 信号 / signal
```

- 演算子の前後は **必ず半角スペース 1 つ以上**。
- 演算子の優先順は **長いものから**(`<->` を `<-` `->` より先にマッチ)。
- `:` 以降がラベル(任意)。
- 接続に登場した ID が未定義なら **暗黙ノード** として自動生成。

### 演算子セマンティクス

| 演算子 | 線種 | 矢印 | 備考 |
|---|---|---|---|
| `-` | 単線 | なし | |
| `->` | 単線 | 終点 | |
| `<-` | 単線 | 始点 | パース時に from/to を入替して `->` 相当に正規化 |
| `<->` | 単線 | 両端 | |
| `..` | 破線 | なし | |
| `.>` | 破線 | 終点 | |
| `=>` | 太線 | 終点 | |

## ラベルと多言語

```
LABEL := SEGMENT ('/' SEGMENT)?
SEGMENT := (生テキスト | STRING)
```

**ルール**:

- ラベル中で **クォート外の `/`** は **日英の区切り**。前=日本語、後=英語。
- クォート内の `/` `:` `=` `#` は文字として扱われる。
- 片言語のみの場合、もう一方の言語モードでも同じ文字列で表示される。

**例**:

| 入力 | 解釈 |
|---|---|
| `10 = 制御部 / control unit` | ja="制御部", en="control unit" |
| `11 = CPU` | ja="CPU"(両モードで CPU と表示) |
| `13 = "I/O" / "I/O interface"` | ja="I/O", en="I/O interface" |
| `14 = "比率 1:2" / "ratio 1:2"` | ja="比率 1:2", en="ratio 1:2" |

## コメント

```
COMMENT := '#' (改行以外の任意の文字)*
```

- `#` から行末までは無視される。
- 行頭・行中のどこでも可。
- クォート内の `#` は文字として扱われる。

**例**:
```pdg
# これはコメント
10 = 制御装置    # 行末コメントもOK
20 = "型番 #A100" / "Model #A100"   # クォート内の # はリテラル
```

## クォート / エスケープ

ラベルに **予約記号**(`/` `:` `=` `#` `"`)を含めたい場合は `"..."` で囲む。

| 入力 | ラベル |
|---|---|
| `13 = "I/O インターフェース"` | `I/O インターフェース` |
| `14 = "比率 1:2"` | `比率 1:2` |
| `15 = "型番 #ABC"` | `型番 #ABC` |
| `16 = "y = ax + b"` | `y = ax + b` |

**制限**: クォート内の `"` のエスケープは現バージョン非対応。

## 図種の自動推論

```
1. もし 包含文が 1 つ以上ある → ブロック図
2. もし ラベル末尾が '?' の符号が 1 つ以上ある → フローチャート
3. もし 符号 '*' が登場する → 状態遷移図
4. もし '<->' 演算子、または 同じノード対 (A,B) に対して
        A→B と B→A の両方の接続がある → シーケンス図
5. それ以外 → フローチャート(直列パイプライン)
```

**判定例**:

| ソース概略 | 判定 |
|---|---|
| `10 : 11 12` がある | ブロック図 |
| `S110 = 条件?` がある(包含なし) | フローチャート |
| `* -> S1` のように `*` がある(包含・? なし) | 状態遷移図 |
| `100 -> 200`, `200 -> 100`(包含・?・*なし、往復あり) | シーケンス図 |
| `100 <-> 200` がある | シーケンス図 |
| `S100 -> S110`, `S110 -> S120`(片方向のみ) | フローチャート |

## 形状の自動推論

### フローチャート時

| 条件 | 形状 |
|---|---|
| ラベル末尾が `?` | ◆ 菱形(条件分岐) |
| 入次数 0 | ⬭ 角丸(開始) |
| 出次数 0 | ⬭ 角丸(終了) |
| それ以外 | □ 長方形(処理) |

### 状態遷移図時

| 符号 | 形状 |
|---|---|
| `*` | ● 黒丸(初期/終端マーカ) |
| その他 | ⬭ 角丸長方形(状態) |

### ブロック図 / シーケンス図

- ブロック図: すべて **□ 長方形**(親は枠付きコンテナ、子は内側の矩形)
- シーケンス図: アクタは **□ 長方形** + 下方向の **破線ライフライン**

## 描画・レイアウト方針

PatentDSL のレイアウトは自動のみで、座標指定は持たない。特許のブロック図で典型的な「機能ラベル付きの中空矩形を線で相互接続する」形式を優先する。

### ブロック図

- 子が 1〜2 個の包含は縦1列に配置する。
- 子が 3 個以上で、子同士が直列の処理チェーンを作る場合は縦1列に配置する。
- 子が 3 個以上で、分岐/並列/スター状の接続の場合は2列グリッド寄りに配置する。
- 入れ子の親コンテナは外側から内側へ描画し、外側コンテナが内側コンテナを塗りつぶさないようにする。
- 同じ親コンテナ内の接続は、その親コンテナの外へ逃がさず、内側の余白通路を優先する。
- 外部ブロックは、既に配置済みの接続先ブロックに近い高さへ自動整列する。
- 外部接続は他の可視ブロックを横切らない経路を優先する。
- 接続先が接続元より明確に上下へずれている場合、横辺に刺すより上辺/下辺へ入る経路を優先する。
- 破線のみは `..`、破線矢印は `.>` として描き分ける。

### フローチャート / 状態遷移図

- 接続関係からランクを計算し、上から下へ配置する。
- 循環がある場合は、最初に到達したランクを優先して配置し、接続自体は描画する。
- 未接続ノードは下方へ追加配置する。

### シーケンス図

- アクタは接続に登場した順に左から配置する。
- メッセージはソースの行順に上から下へ配置する。
- ライフラインは破線で描画し、矢印マーカは付けない。

## 診断(エラー / 警告)

パーサと検証器は次の診断を発する:

| 種別 | コード | 例 |
|---|---|---|
| error | `parse` | `構文不明: "10 == X"` |
| error | `cont-child-invalid` | `包含の子として不正なトークン: "1@1"` |
| warning | `redef` | `符号 "10" は再定義されました` |

エラーがあっても可能な範囲で描画は続行される(堅牢性優先)。
接続や包含だけに現れた未定義符号は暗黙ノードとして自動生成され、UI の符号表では薄色で表示される。

## BNF風文法

```ebnf
document      = { line } ;

line          = blank
              | comment
              | def_line
              | cont_line
              | conn_line ;

blank         = WS* CR ;
comment       = '#' (~CR)* CR ;

def_line      = id WS* '=' WS* label CR ;
cont_line     = id WS* ':' WS+ id { WS+ id } WS* CR ;
conn_line     = id WS+ op WS+ id (WS* ':' WS+ label)? CR ;

op            = '<->' | '=>' | '->' | '<-' | '.>' | '..' | '-' ;

id            = ID_CHAR+ ;
ID_CHAR       = 'A'..'Z' | 'a'..'z' | '0'..'9' | '_' | '*' ;

label         = segment (WS* '/' WS* segment)? ;
segment       = string | raw_text ;
string        = '"' (~'"' & ~CR)* '"' ;
raw_text      = (~'/' & ~'#' & ~CR)+ ;

WS            = ' ' | '\t' ;
CR            = '\n' | '\r' '\n' ;
```

**注意**: `def_line` で `=` の直後が `>` の場合は否定先読みで除外する(`=>` は演算子のため接続文)。

## 仕様の境界(やらないこと)

- 連鎖記法 `A -> B -> C`(現バージョン未対応、各行に分ける)
- 複数の図を 1 ファイル(1図1ファイル)
- 任意 SVG の埋め込み・カスタム形状定義
- 色指定・スタイル指定(特許図面の慣習に従い黒線のみ)
- 自由な座標指定(レイアウトは自動のみ)
- セル / レーン(swimlane)
- alt / loop / parallel のシーケンス拡張
- カスタムフォント・配色テーマ

これらは記法を読みやすく保つため意図的に外しています。将来再評価される可能性はあります。
